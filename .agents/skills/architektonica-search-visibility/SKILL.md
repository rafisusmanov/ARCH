# Search Visibility

## Поиск не должен диктовать смысл

Работай в двух режимах. **На этапе архитектуры** определяй поисковое намерение, адреса, языковые версии, таксономию и внутренние связи; не придумывай частотности и не пиши текст до выбора задачи страницы. **После авторского текста** дорабатывай метаданные, заголовки и извлекаемость фактов, сохраняя идею. Не превращай главную в каталог поисковых фраз.

## Что делать

1. **Намерение запроса.** Исходи из выбранной услуги Services, её аудитории и задачи. Проверяй язык каждой практики самостоятельно, не ограничивай исследование digital, AI или примерами известных проектов. Не придумывай частотность или позиции без инструментов.
2. **Структура.** Title, description, H1 и логические H2. Содержательные ответы на ключевые вопросы. Нет обязанности использовать все ключи в первых 100 символах.
3. **Страницы услуг.** Каждая практика имеет свою логику, профессиональный язык и вход по задаче. Объясняй состав работ и возможные артефакты без обязательного примера проекта.
4. **Роли источников.** Главная представляет компанию и коммерческое предложение, не портфолио из иллюстраций Brand Core. Кейсы только по необходимости, см. `../../../methods/editorial-source-boundaries.md`.
5. **Entity consistency.** Название компании ARCHITEKTONICA, подтверждённые имена, ID услуг и предметные связи одинаковы во всём корпусе. Schema.org только по проверяемым сведениям; упоминание проекта не обязательно.
6. **AI search.** Пиши точные определения, компактные цитируемые абзацы, вопросы и ответы там, где уместно. Хорошо сформулированный факт полезнее «секретов оптимизации для нейросетей».
7. **Внутренние связи.** Связывай страницы по задаче посетителя и утверждённой IA. Услуга может вести к направлению, связанному предложению или контакту без кейса. Ссылка на работу допустима только при подтверждённой связи и публикационном статусе цели; отсутствие кейса не означает дефект услуги.
8. **Проверка.** Если есть реальная аналитика/поисковая консоль — используй её; если нет, обозначь гипотезу и способ проверки. После SEO-изменений передай текст на критическую редактуру, проверку фактов и сравнение качества языка по `../../../methods/editorial-source-boundaries.md`.

## SEO без пустого объёма

Не добавляй FAQ, вторую «Как мы работаем», новые H2 или повторный CTA только потому, что они часто встречаются на коммерческих страницах. Каждый новый раздел должен отвечать на отдельный подтверждённый запрос читателя. Сначала сохранить авторскую мысль и предметную ясность, затем оформить поисковые поля. Дублирующие объяснения не становятся полезнее от ключевых слов; SEO title и meta description не примешивать к публикационному телу страницы без отдельного запроса на пакет метаданных.

## Специализированные методики (читать по задаче)

**Этап 02 / семантика 87 публичных услуг (81 исторический ID сохранён):** [keyword-serp-research](references/keyword-serp-research.md) — подтверждённый спрос, RU/Google/Яндекс, SERP, intent, кластеры, сохранение catalogue_name/ID и [действующий публичный каталог](../../../planning/stage-02/public-service-catalogue.json); не придумывать цифры.

**IA / связи / конкурирующие страницы:** [site-structure-linking](references/site-structure-linking.md) — каноническое намерение, `Direction → Service ↔ Case ↔ Article`, выявление сирот, статусы и RU/EN. Утверждённый sitemap не пересматривать без решения владельца.

**После черновика текста, до утверждения:** [geo-aeo-content-evidence](references/geo-aeo-content-evidence.md) — прямая польза, экспертная доказательность, цитируемые определения и независимая фактологическая проверка. Авторство текста остаётся у главного исполнителя по канону голоса `../../../methods/site-voice-and-consistency.md`, для портфолио — Portfolio Case Writer; факты — у утверждённых источников.

**Этапы 02/05–07:** [page-publishing-audit](references/page-publishing-audit.md) — пакет H1/title/meta/schema, запуск и проверка реально работающих страниц; краткий SEO/GEO/AEO-чек-лист, адаптированный по идее SNLabat. Инструкция не означает, что проверка сайта выполнена.

Внешние заимствования по идеям, закреплённые версии и ограничения прав: [реестр источников](references/EXTERNAL_SOURCES.md). Не выполнять все четыре рецепта при каждом запросе — открывать только относящийся к текущей задаче. Не устанавливать чужой рантайм/скрипты и не добавлять навыки ради чек-листа.

## Запрещать? Нет. Разделять

`Креативный H1` может быть необычным, если подзаголовок объясняет деятельность. `SEO title` может быть прямым и предметным. Это две разные поверхности с разными задачами.

Для услуги H1 передаёт её предмет и авторскую мысль, title уточняет поисковое намерение и бренд. Это разные задачи; название проекта не требуется ни в одном поле. Формулировки создаются заново для конкретной страницы, а не берутся из архивного примера.

## GEO без гарантий

Никакой skill не обеспечивает автоматически цитирования ChatGPT/Google/Perplexity. Не повторяй непроверенные показатели эффективности приёмов. Смотри методики: `../../../references/github-sources.md`; факты в проектных файлах.

## Результат

Для существующей страницы: улучшенная версия + SEO title, meta description, H1/H2, сохранённый утверждённый URL, идеи внутренних ссылок; новый slug предлагать только для ещё не утверждённого маршрута или при отдельном решении владельца. Для стратегии — компактная карта страниц и поисковых намерений с пометкой, что объёмы и конкуренция требуют актуальных данных.
