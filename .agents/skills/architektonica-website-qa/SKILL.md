# ARCHITEKTONICA — Website QA

## Назначение и триггер
Используй **на задачах проверки работающего сайта**: ревью реализованной страницы/блока, регрессии, release gate, готовности сложной сцены, мобильной или кроссбраузерной проверки. Не запускай при написании текста, выборе концепции или чистой IA без работающего интерфейса. Проверяй реальные страницы ARCHITEKTONICA-WEB, не «доказательство» в виде Markdown. Для оценки действительных страниц сопоставляй с утверждённым содержанием/дизайном; если его нет, разделяй базовые стандарты и незавершённые решения.

Общие правила и источники проекта: [AGENTS](../../../AGENTS.md), [производственная методика](../../../methods/engine-template-adaptation.md), [утверждённая дорожная карта v2](../../../references/project/ARCHITEKTONICA_SITE_PLAN_V2.md). Полный перечень сценариев и критериев: [QA CHECKLIST](references/QA_CHECKLIST.md).

## Порядок проверки
1. **Скоуп.** Получить ссылку на PHP preview или локальный сервер, текущий commit, список маршрутов/локалей, утверждённый эталон, целевые устройства и среду. Нет URL или нет работающего браузера — не утверждать, что визуальный QA выполнен.
2. **Маршруты и контент.** Проверить главную, направления/услуги (действующий публичный каталог 6/17/87; 81 исторический ID для совместимости), карточки и детали кейсов, блог/статьи, About, вакансии, контакты, 404, RU/EN и связанные переходы. Не публиковать демо-кейсы Engine; черновики/пустые состояния не выдавать за готовые материалы. Проверить canonical/hreflang и ссылочную целостность только для утверждённых URL.
3. **Функции.** Рабочее меню, keyboard focus, формы и валидация, ошибки и подтверждения. Для preview с намеренно отключённой формой проверять отказ и указывать RELEASE BLOCKER, а не считать форму рабочей.
4. **Визуальные сравнения.** Утверждённые baseline-скриншоты, те же размеры, браузеры, шрифты, данные, состояния и отключённая/фиксированная анимация. Playwright для Chromium, Firefox и WebKit, раздельные результаты; iOS Safari и Android Chrome дополнительно на реальных устройствах. Не обновлять baselines без согласования изменившегося дизайна.
5. **WCAG 2.2 AA.** axe-core для автоматизируемых нарушений плюс ручные сценарии: Tab/Shift+Tab/Enter/Escape, видимый и не перекрытый фокус, логичный порядок DOM/заголовков, управление меню/диалогами, ошибки форм, контраст, масштаб/reflow 320 CSS px, touch targets, screen readers (VoiceOver и NVDA) и доступность WebGL-контента. Автоскана недостаточно для заявления «WCAG соответствует».
6. **Motion и устройства.** Проверить обычный режим и `prefers-reduced-motion`, клавиатуру/touch, смену ориентации, scroll lock, отсутствие зависания Lenis/ScrollTrigger, разрушение/offscreen GSAP-сцен и WebGL контекста. Правила ресурсного цикла — в производственной методике; диагностика `animation-performance` по задаче, другие навыки с `disable-model-invocation` не вызывать автоматически.
7. **Производительность и надёжность.** Данные Performance panel/trace, Long Tasks, память/GPU, Lighthouse и полевые CWV — различать; повторять на целевых смартфонах и ограниченной сети. Бюджеты сцен согласовывать до реализации, не выдавать один эмуляционный прогон за реальные устройства.
8. **Отчёт.** Для каждого P0/P1/P2: точный маршрут, шаги, устройство, браузер, скриншот/trace, ожидаемое и фактическое, масштаб воздействия, ответственный, статус исправления и повторный прогон. Разделить PASS / FAIL / NOT RUN, не «ставить зелёный» по отсутствию доказательств.

## Инструменты (только если действительно установлены в WEB/окружении)
- Playwright: `npm ci`, затем `npx playwright test --project=chromium`, `--project=firefox`, `--project=webkit` **только после** создания конфигурации и test harness в WEB. Зависимости не добавлять в Creative ради инструкций.
- `agent-browser screenshot`, `agent-browser diff screenshot --baseline baseline.png`, `agent-browser a11y --json` доступны при отдельной установке CLI; работать с контролируемым preview и согласованными эталонами. CDP/Chromium-аудит не эквивалентен Safari/iOS.
- axe-core помогает выявить часть проблем, но ручные WCAG-сценарии обязательны. Локальная автоматика предпочтительнее платных облачных сервисов и автономных браузерных агентов.

## Граница ответственности
Этот навык **описывает проверку**, но не означает, что Playwright, axe, агент-браузер, WCAG или профайлер уже запущены. Готовые тесты и зависимости живут в `ARCHITEKTONICA-WEB` в отдельном PR на этапе разработки/QA. Не менять production, не устанавливать сторонние hook/CLI автоматически и не выполнять пользовательские сценарии на сторонних сервисах без явной необходимости.

Условие готовности страницы: утверждённый текст не искажён, интерактивность и навигация работают, недоступного контента нет, P0/P1 устранены, причины непроверенных пунктов зафиксированы. Не ставить PASS там, где нет свидетельства.
