# ARCHITEKTONICA — PHP / Beget: контроль запуска (этапы 05–07)

**Это инструкция приёмки, не выполненный аудит.** Реальные технические действия и тесты выполняются в `ARCHITEKTONICA-WEB` отдельными PR. Не делать полный аудит шаблона стартовым творческим этапом. Технические изменения проверять применительно к затронутым компонентам. Существенная визуальная переработка Engine уже утверждена: сохранять сильные решения, слабые перерабатывать или заменять по содержанию и критериям качества; эта техническая инструкция не ограничивает объём утверждённого редизайна.

## Перед релизом
- **PHP:** версия и расширения Beget подтверждены; PHP lint по всем исходникам; отключены `display_errors` и `APP_DEBUG`; ошибки в закрытых журналах, не в HTTP-ответе.
- **Apache и маршруты:** на реальном Apache/Beget проверить rewrite для `/`, `/about`, услуг, кейсов, статей, будущих RU/EN маршрутов, 301/404/405, ссылок и статики. Встроенный `php -S` не является проверкой Apache.
- **Приватные файлы:** HTTP-запрет доступа к `includes/`, `pages/`, `scripts/`, `tests/`, `.env`, конфигурации, резервным копиям и исходникам PHP; разрешать только нужную публичную статику. Проверить обходы через URL-encoding и точечное ACME-исключение.
- **Экранирование:** HTML/атрибуты/URL/JSON-LD проходят контекстное экранирование; входные данные валидируются и нормализуются; нет вставки небезопасного HTML из статей.
- **Формы:** предпросмотр пока блокирует отправку. В production нужны CSRF/антиспам, rate-limit в общем хранилище, ограничения размеров, единая idempotency-запись, безопасная доставка/сохранение, ложный/повторный POST не создаёт заявку. Не выдавать 200 браузерного ответа за успешную доставку.
- **Журналы:** без телефонов/email/текста обращения в доступных логах и аналитике; адекватные права, хранение и ротация, восстановление после сбоя.
- **HTTPS:** корректные SSL, заголовки безопасности, перенаправления, canonical и исключение mixed content. Политики CSP настраивать по проверенному составу Engine/Webflow скриптов, а не ломать эффект без теста.
- **Индексация:** до подтверждения контента `content_approved=false` и preview noindex остаются. При запуске проверить все слои: PHP-заголовки, Apache, Vercel preview, robots, sitemap, hreflang, JSON-LD. Не снимать запреты одним переключателем.
- **Резервирование:** сделан проверяемый backup файлов/конфига/данных; выполнить **тест восстановления** в изолированной среде. Описать rollback на предыдущую рабочую версию, ответственных и smoke проверки после отката.
- **Релизные ворота:** владелец утверждает факты/контент и контакты; технический ответственный подтверждает URL/формы/безопасность/логирование/SEO, тестировщик — матрицу браузеров, мобильных устройств и WCAG. Пункты NOT RUN видны, не маскируются PASS.

## Пример безопасного smoke-теста
В WEB использовать существующие `python3 -m unittest discover -s tests -v` и `node --test tests/*.test.cjs`, `php -l` для каждого PHP-файла. Для Apache/Beget добавить отдельный сценарий с конкретным сервером и указанием среды. Не запускать тестовую отправку в реальный почтовый ящик без безопасного стенда.

Применять вместе с [Website QA](../skills/architektonica-website-qa/SKILL.md) и его [чек-листом](../skills/architektonica-website-qa/references/QA_CHECKLIST.md): этот документ покрывает сервер и выпуск, Website QA — страницы, браузеры, доступность и сцены. Ни один пункт этих документов не означает, что production уже готов.
