# ARCHITEKTONICA — проверка реальной эффективности навыков

**Цель:** проверять не только YAML, зеркала и наличие файлов, но и качество решений агента. Это **ручная экспертная оценка по фиксированным заданиям**, а не автоматическое доказательство качества модели. Не менять утверждённые тексты или факты ради прохождения теста.

При оценке агента отдельно фиксировать, выполнил ли он [протокол поэтапной работы](agent-expert-stage-protocol.md): определил текущий этап по подтверждениям, прочитал уместные SKILL.md, не нарушил gate владельца, привёл доказательства результата и повторно проверил исправления. Утверждение плана v2 не засчитывается как утверждение его этапов.

**Актуальный task/skill baseline (12.11.2026):** [матрица 01–07](task-skill-matrix.yaml), [правила чтения источников и проверки журналов](task-execution-evidence.md), [валидатор и preflight](../scripts/task_skill_router.py). Сценарии из `tests/fixtures/skill-evaluation-cases.json` связаны с `routing_task_id` и обязаны точно воспроизводить required_skills своей задачи. Структурный тест на эти связи не заменяет прогоны настоящего агента. Каталог публичного предложения – **6/17/87**, исторические 81 ID сохраняются, но не являются числом продаваемых услуг.

## Процедура
1. Записать commit Creative, модель/агента, дату, среду, режим без памяти и одинаковые исходные факты.
2. Для каждого задания из `tests/fixtures/skill-evaluation-cases.json` открыть новый чистый контекст. Дать агенту обычное задание с инструкциями Creative. Отдельно провести baseline без соответствующего навыка, если среда позволяет.

   Если среда не позволяет открыть независимые контексты, выполнить доступный контрольный прогон в текущем контексте и сохранить его результаты отдельно. Чистые контексты и baseline отметить NOT RUN; такой прогон не заменяет полную процедуру. Самопроверка автора не является независимой оценкой человеком: пять оценок и итог принятия остаются неподтверждёнными до рецензии.
3. Проверить, что агент реально открыл уместный SKILL.md и нужные ресурсы, не активировал явные-only навыки без запроса, сохранил прямые решения владельца и проверял факты по Fact Bank/Case Studies.
4. Оценить результат по пяти критериям (каждый **0/1/2**): фактическая корректность; брендовый голос и ясность; уместность выбора навыков; соответствие структуре/реальной задаче пользователя; соблюдение ограничений проекта (Engine, действующий каталог 6/17/87 с 81 историческим ID, стадия кейса, PHP, reduced motion).
5. **Критический провал независимо от суммы:** выдуманный результат/клиент/цена, публикация непроверенных фактов, удаление услуги, самовольная смена стека, подмена готовой работы имитацией проверки, обход explicit-only.
6. Для каждой работы сохранять короткую карточку: идентификатор кейса, использованные навыки, 5 оценок, наблюдения и исправление. Включать ссылку на конкретный commit/PR. Оценивание проводит человек; не заменять его заявлением «30 tests passed».

**Оценка:** 8–10/10 при отсутствии критических ошибок — удовлетворительно; 6–7 — доработка; 0–5 — не принят. Это внутренняя рубрика контроля качества и не показатель конверсии/реакции клиентов.

## Базовые пять сценариев; дополнительные допускаются без изменения правил
- Главная: ясно представить компанию и три опоры, создавая оригинальный авторский текст **без выдуманных фактов и неподтверждённых показателей**.
- Услуга: конкретное описание, место в 17/81 и правильные связи с материалами.
- Кейс с недостатком исходных фактов: не приписывать концепции статус внедрения.
- Микротекст: коротко, понятно, конкретное действие и корректные ошибки.
- Иммерсивная сцена: UX-обоснование, пространственная глубина, reduced-motion, mobile fallback и способ измерения без выдуманных FPS.

Запуск структурной проверки кейсов из корня: `python3 -m unittest tests.test_skill_evaluation -v`; это **не** запуск генерации агентом и не измерение качества его ответов.

Референс разработки и сравнения навыков: [Anthropic skill-creator](https://github.com/anthropics/skills/tree/main/skills/skill-creator) (Apache-2.0). В этот репозиторий не импортируется сторонний исполняемый код.

## Аудиторский статус выполнения, 02.11.2026

Пять контрольных сценариев и структурные unit-тесты **не являются** пятью реальными независимыми прогонами агентов. До сохранения пяти оригинальных результатов, SHA использованной версии навыков, экспертных оценок и решения владельца эффективность полной агентной цепочки имеет статус **NOT RUN / NOT VERIFIED**. Редакционная приёмка Stage 02 требует живого чтения текстов человеком, а не только PASS в CI. Оценивать отдельно оригинальность, обоснованность, общий голос, границы SEO, фактические обещания; не заполнять фиктивные баллы.
