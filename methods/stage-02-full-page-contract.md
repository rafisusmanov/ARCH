# Stage 02 – контракт целой страницы и изучение WEB (10.11.2026)

**Решение владельца:** текст и композиция должны создаваться для полного маршрута страницы, а не для одного красивого блока. Этот документ уточняет Stage 02 действующего семиэтапного плана, **не создаёт этап 02.5 и не разрешает запись в WEB**. [План v2](../references/project/ARCHITEKTONICA_SITE_PLAN_V2.md), [AGENTS](../AGENTS.md), [WORK_MAP](../planning/stage-02/WORK_MAP.md).

## Перед написанием каждой новой публичной страницы

1. **Предмет и статус.** Подтвердить страницу в утверждённой IA, текущие решения владельца и границы одобрения. Открыть Brand Core, Services, Fact Bank и Case Studies только по назначению. Страница `/process` отменена, `/services` находится в редакционном обсуждении.
2. **Read-only WEB-инвентаризация.** Прочитать текущие PHP-страницы, вложенные partials/components, источники данных, CSS/JS-поведение, media и маршруты. Составить последовательность всех существующих блоков: от первого экрана до футера. Нельзя путать неполную демо-страницу с утверждённой архитектурой сайта.
3. **Сверка с IA и читателем.** Определить, что посетитель должен узнать/сделать; проверить доступ ко всем обязательным направлениям, внутренние переходы, сопутствующие проекты, материалы и контактный сценарий. Не добавлять выдуманные обещания, цифры, проекты и блоки по квоте.
4. **Исследование референсов.** [Only.digital](text-reference-only-digital.md) изучать по качеству речи, архитектуре подачи и UX, `WEB/reference/` – по типографике, визуальному ритму, многослойности и выразительным приёмам. Адаптировать лучшие механики к собственной IA без буквального переноса чужих текстов. Указать, что подтверждено скриншотами, а что требует просмотра motion/браузера.
5. **Карта решения для каждого блока:** `текущий WEB-блок → задача для читателя → retain / refine / extend / replace / omit → требуемый текст / медиа / ссылка`. Предпочтение – **сохранить и доработать** удачное в Engine; не переделывать сайт полностью только ради демонстрации нового дизайна. `replace` – исключение с предметной причиной. В Stage 02 это редакционная рекомендация; финальные компоненты и эффекты утверждаются на Stage 03–04.
6. **Полная содержательная композиция:** первый экран, основные разделы, навигация и глубина каталога, необходимые доказательства, контакты/CTA, возможные FAQ, SEO/метаданные и медиаплан. Для каждого блока сформулировать отличный от других смысл; не выдавать список карточек за готовую страницу. Утверждённый публичный каталог 6/17/87 доступен на соответствующих уровнях, но не обязан занимать весь первый экран; 81 исторический ID сохранён для совместимости.
7. **Единый авторский текст:** цельная редакция со всеми нужными секциями; один ведущий исполнитель, применимые экспертные роли. `Copy Studio` удалён как самостоятельный навык; упоминание в историческом утверждённом v2 означает функцию основного автора, **не требование восстановить его**.
8. **Проверка до ответа:** полнота смыслового маршрута, отсутствующие блоки, все ссылки/CTA, читабельность, факты, актуальные решения, дубляжи, язык трёх самостоятельных областей, критическая редактура и сравнение с Only. Проверку `PASS/FAIL/NOT RUN` фиксировать честно; зелёный CI не является редакционной рецензией.
9. **Gate:** показать владельцу одну полную версию страницы и краткую редакционную карту того, что в будущем сохранить/доработать/расширить в WEB. Без его явного утверждения **не менять публикационный текст в Creative и никакие файлы WEB**. После утверждения Stage 02 фиксировать копию в Creative; программирование и дизайн WEB – по отдельному разрешению на соответствующем этапе.

## Специальная проверка /services

- Шесть обзорных карточек Engine – **важная удачная часть**, но **не вся страница**. Текущий WEB `pages/service.php`: первый экран → повторяющиеся service-card → CTA → демонстрационный Pricing Plan. Изучить также `pages/service-detail.php`.
- **Утверждено владельцем 10.11.2026:** шесть групп, доступ к 17 направлениям и **87 уникальным публичным услугам**. Исторические 81 ID не удалять, новые svc-082…092 не присваивать старым позициям и не переиспользовать; в публичном интерфейсе показывать услуги только по [Stage 02 каталогу](../planning/stage-02/public-service-catalogue.json), а не по старому 81-позиционному снимку. Не сводить всю страницу к шести карточкам. Отдельно утверждаются публикационный текст и внедрение.
- `Pricing Plan` содержит демонстрационные долларовые цены, поэтому не использовать его как реальное предложение без фактов; предложить содержательную альтернативу для будущего дизайна.
- Фармацевтические предметные работы, отмеченные владельцем как кейс, не объявлять узкой исчерпывающей специализацией прикладного AI. Обобщать предложение; реальную классификацию `svc-*` пересмотреть отдельно без тихого удаления ID и без вымышленных дополнительных услуг.
- Кибербезопасность раскрывать как отрасль/направление в релевантной группе, подробную техническую детализацию – на собственной странице с проверкой исходного документа.
- В карту страницы включить реальные элементы навигации, графику, 3D-медиа, внутренние переходы, текст каждого смыслового блока, мобильный сценарий как задание для будущего Stage 03.

## Проверка качества

`Смысловая полнота: PASS` разрешена только если составлена карта всей страницы и объяснены судьба каждого существующего блока, обязательные входы утверждённой IA и содержание новых нужных блоков. Наличие одного H1, шести карточек и CTA – **FAIL**. Механический unit-тест проверяет наличие и связность этого контракта, **не** качество самой будущей страницы и не факт его выполнения моделью.
