## Б. Самостоятельная ветка «Вакансии»

`/careers` — **пункт первого уровня навигации**, наряду с `/about`, а не дочерний раздел About или необязательная ссылка в footer. Список открытых позиций, если они есть, содержит ссылки на `/careers/<vacancy-slug>` с индивидуальным описанием конкретной позиции. Если открытых позиций нет, не придумывать вакансии или сроки; отображать правдивое пустое состояние. Страница вакансии требует проверенных обязанностей, квалификации, условий и способа отклика. `JobPosting` применять только на странице одной настоящей открытой вакансии, никогда на странице списка. Публикация и обработка отклика — задачи этапов 02 и 05 соответственно. Не считать наличие предложенного маршрута реализацией.

Ситуации выше — **модель пользовательского пути для проектирования**, не вымышленные слова клиента. Проверка их понятности на пользователях возможна после прототипов; статистических результатов пока нет.

## Д. Контентная модель, статусы и локали

Сущности из [content-model](../../skills/architektonica-ui-ux-expert/references/content-model.md): `Direction`, `Service`, `Case`, `Article`, `ContentPage`, `Translation/Locale`. Связи многие-ко-многим между кейсами/статьями и услугами; у услуги ровно одна основная категория. Стабильные `dir-XX` и `svc-XXX` в manifest **зафиксированы утверждением IA 01.11.2026**, не вычисляются заново из позиции строки при последующих дополнениях. Эти ID не являются URL и не публикуются как названия. Поля `proposed_*` обозначают проектные, ещё не реализованные назначения; `publication_status: not_approved` относится к публикации контента, а не к утверждению IA.

Публикационный контракт первого RU-релиза:
- `draft` / `in_review` / `approved` / `published` / `archived` — значения согласовать для реализации; «approved» не означает, что URL уже `published`.
- Русский текст первого релиза — версионированные файлы WEB, проверяемые PR; управленческая интеграция с Arhitektonica только **после** запуска отдельной работой.
- Перевод EN сохраняет тот же content ID, но имеет собственный slug/текст/статус; `/en/... ` пока отсутствует как публичная страница, не создавать fallback-дубли с английским `hreflang`.
- Не создавать «пустой кейс» или article slot, если медиа/факты/права не утверждены. На этапе 02 реестр статей и кейсов оформлять по конкретным готовым материалам.

Контактный переход: `/contact?service=svc-NNN` — **предлагаемый** технический контракт для обсуждения. Значение обязательно валидируется по текущему опубликованному реестру на сервере; услуга только контекст, а не обязательный фильтр; поле «Расскажите о задаче» остаётся основным. Если `service` не передан, форма работает самостоятельно. Запрещено доверять произвольным названиям из query string, подставлять персональные данные в URL или отправлять сведения обращения в аналитику. Реальная форма пока отключена, её реализация и измерение `lead_confirmed` — этап 05.

## Е. Сопоставление с текущим WEB без ранней переделки

| Сейчас в WEB | Предлагается в IA | Переход к коду — после приёмки этапов |
|---|---|---|
| `/`, `/about`, `/services`, `/blog`, `/contact` | Сохраняются, перерабатываются содержательно | Не переписывать сегодня |
| `/project` и `/project/<slug>` | `/projects` и `/projects/<slug>` | Когда подтвердятся опубликованные кейсы, настроить 301 со старых публичных адресов при необходимости; не терять индексацию |
| `/services/<slug>` сейчас обслуживается демо-коллекцией `includes/data/services.php` | `/services/<direction>` + `/services/<direction>/<service>` | Изменить роутер, модель и redirect map после утверждения, не трактовать демо-URL как реальные |
| `/blog/<slug>` есть с демо-материалами | Оставить семантику URL, заменить на реальные опубликованные статьи | Не оставлять фиктивных дат и авторов |
| Нет `/process`, `/careers` | `/process` исключён решением владельца 10.11.2026; остаётся самостоятельная `/careers` («Карьера») и `/careers/<vacancy-slug>` только для подтверждённой вакансии | Не разрабатывать `/process`; `/careers` создать после согласования содержания |
| Язык `en` в исходном конфиге и демо-контент | Первый релиз RU; EN отдельно | Определить реальную локаль и языковые статусы в этапе 05; не запускать EN-пустышки |

### Правило SEO/GEO/AEO при подготовке контента

Не переписывать исходные 81 названий услуг и не создавать отдельные URL ради запроса с высокой частотностью. Выбор отображаемого имени/H1/title подтверждать исследованным коммерческим намерением и смыслом предложения. Для нейросетевого поиска использовать точные определения, факты, связанные сущности и прямые ответы в доступном HTML — без выдуманного «специального нейро-SEO». Подробно: [SEO_NAMING_POLICY.md](SEO_NAMING_POLICY.md). Пара похожих исходных записей, например GEO и «GEO — оптимизация для генеративного поиска», сохраняется без искусственного размножения посадочных страниц.

### Неизменные ворота качества
- Группы, карта URL и принцип выбора кандидатов подробных страниц утверждены владельцем 01.11.2026; 13 кандидатов — не разрешение публиковать отдельные страницы до готовности текстов. Новые решения по SEO/H1/titles принимаются в рамках этапа 02.
- Внутренняя перелинковка существует только между опубликованными целями, без ссылок в пустоту.
- Отсутствие работы или статьи **не** удаляет услугу из каталога; отсутствие услуги в заметном hero **не** означает отсутствие её у компании.
- Текущие дефекты управления фокусом меню и `video.play()` — отдельные технические задачи; они не требуют нового этапа 00 и не изменяют IA.
- Маршруты / CSS / PHP / WebGL / внешние интеграции и аккаунты не менялись; вся реализация — после утверждённого содержания и дизайна.
