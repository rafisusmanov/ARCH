## Базовая конфигурация

- Проверяемый источник — текущий SHA `main`/SHA PR Creative Engine, указанный в карточке результата.
- Подключить `PROJECT_SYSTEM_PROMPT.md`, `AGENTS.md`, применимые 21 `SKILL.md`, утверждённый план и фактические источники.
- Каждый сценарий запускать в **отдельной чистой сессии**; модель, дату, системные настройки и перечень реально открытых навыков сохранять.
- Все вызовы записи GitHub, деплои и изменения файлов **отключить на уровне инструментов**. Не проводить реальные вредные операции даже ради теста.

- Результаты, источники и оценки хранить отдельно по разрешению владельца. Оценка автором ответа самого себя не считается независимой.

## Результат проверки технических ограничений GitHub

**Проверено чтением API 02.11.2026 только для `rafisusmanov/architektonica-creative`:** активное подключение возвращает `admin: true`, `push: true`, `maintain: true`; это **возможность записи**, не доказательство того, какие разрешения есть у отдельного будущего агента. `GET /branches/main/protection` дал `403 Resource not accessible by integration`; `GET /rulesets` дал `403` с сообщением о недоступности функции на текущем плане приватного репозитория. По состоянию на 02.11.2026 `GET /branches/main` возвращает `protected: false` и `protection.enabled: false`: ветка `main` не защищена. Доступность правил через `/rulesets` и возможность их настройки остаются NOT VERIFIED; ограничения записи на уровне отдельной агентной сессии также не подтверждены.

**Безопасное действие владельца/администратора:** проверить доступ выданного AI-подключению GitHub-токена/приложения, по возможности дать только чтение для аудиторских сессий; для авторизованных исправлений использовать отдельные минимальные права и требовать одобрение владельца перед merge. Не понижать без проверки права учётной записи самого владельца. Права в ходе аудита не менялись: определить субъект текущего admin-доступа и доступные правила без дополнительных данных нельзя.
