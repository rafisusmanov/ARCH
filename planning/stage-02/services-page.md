## Когда одной услуги недостаточно

Разработка торговой платформы может включать UX/UI, программирование, интеграции, аналитику и маркетинг.

Для корпоративного AI-решения могут потребоваться подготовка данных, разработка модели, интеграция с существующими системами и кибербезопасность.

В таких проектах важно определить границы каждой работы и согласовать технические и организационные решения.

ARCHITEKTONICA объединяет необходимые направления в рамках общей задачи. Если нужна одна самостоятельная услуга, её можно заказать отдельно.

## Спецификация UX (служебное приложение; не публикационный текст)

- Решение 20.11.2026: [шесть страниц направлений](services-direction-flow.md). Маршрут «Изучить возможности»: шесть визуальных входов → одна из шести страниц → внутренние категории и услуги по запросу → контекстное обращение. 17 категорий и 84 услуги не имеют самостоятельных страниц. Числовые подписи и терминологию утверждённого снимка адаптировать при реализации к текущему каталогу.
- Маршрут «Найти конкретную услугу»: поиск по названиям, направлениям и контролируемым синонимам; результаты связаны с действующими ID. Пентест и DevSecOps раскрываются внутри текущей кибербезопасности, не как дополнительные SKU.
- Единственный источник 84 названий (`display_title` для клиента, `title` для профессионального уровня), кратких описаний, поисковых синонимов и ID: public-service-catalogue.json; копию 84 строк в этом документе не создавать во избежание рассинхронизации.
- Desktop/mobile/touch/keyboard: раскрытие не зависит от hover и анимации; обеспечить доступный HTML fallback, работающие переходы и корректные фокус-состояния при отдельной реализации WEB.
- WEB Engine: hero → 6 обзорных блоков → каталог с поиском → комплексные задачи → проекты → CTA → footer. Не переносить демонстрационный Pricing Plan с вымышленными ценами. Реальный WEB пока только для чтения.
- SEO-метаданные, URL отдельных услуг, медиа, браузерные сценарии и технический запуск не включены в это утверждение; это будущая самостоятельная работа.
