# ARCHITEKTONICA – раскрытие услуг и переход к обсуждению проекта

**Решение владельца 20.11.2026:** `structure_approved`. На вопрос о последовательности «общая страница услуг → шесть групп с направлениями → Подробнее → страница выбранного направления с краткими описаниями входящих услуг» владелец ответил: «Да, хорошо, ладно, давай. Делаем.» Утверждена структура раскрытия, не дословная редакция страниц направлений и не реализация WEB.

**Главный принцип:** Сайт должен быть понятен без чтения. Интересен при просмотре. И содержателен при углублении.

## 1. Общая страница /services

Сохранять [утверждённую страницу](services-page.md). Первый экран → шесть визуальных групп с названиями входящих в них 17 направлений и переходами «Подробнее» → поиск по всем услугам → комплексные задачи → проекты → «Обсудить проект».

Группы – обзорные входы, а не шесть отдельных услуг и не обязательные промежуточные страницы. Названия всех направлений доступны внутри соответствующих групп. Переход «Подробнее» у направления ведёт сразу на страницу направления; раскрытие группы, если используется в интерфейсе, не требует отдельного URL. Поиск ведёт к нужной услуге без обязательного просмотра всех групп.

## 2. Страница направления

- Название направления, выразительный первый экран и краткий смысл предложения.
- Все входящие услуги с точными названиями из [действующего каталога](public-service-catalogue.json); видимые названия, краткие предметные описания по запросу, без обязательного длинного чтения.
- Релевантные проекты, когда уместны и материалы подтверждены; не делать кейс обязательным доказательством каждой услуги.
- Короткое объяснение подхода к предмету, если оно добавляет смысл; финальный CTA «Обсудить проект».

Содержание и порядок блоков адаптируются к конкретной дисциплине. Для первого образца выбрано направление `dir-04` «Сайты и цифровые продукты» (11 услуг), проектный маршрут `/services/websites-and-digital-products` согласно [IA](../stage-01/IA_PROPOSAL.md). После утверждения его редакции последовательно готовить другие направления. Группа «Сайты и цифровые продукты» включает также отдельное направление электронной коммерции (2 услуги); не смешивать 11 услуг направления с 13 услугами группы.

## 3. Выбор услуги и обсуждение проекта

Выбор услуги раскрывает её краткое описание на странице направления. CTA «Обсудить проект» передаёт выбранный стабильный service ID в утверждённый [онлайн-мини-бриф](contact-page.md). Посетитель может изменить выбор или обсудить задачу без точного названия услуги. Отправленный бриф создаёт обращение во внутреннем кабинете компании; клиентский доступ к Client OS открывается только после договора и оплаты согласно [решению владельца](../../references/project/OWNER_DECISION_2026-11-18_CONTACT_CLIENT_OS.md).

Все 84 услуги доступны по актуальной таксономии 6/17/84, но не требуют 84 самостоятельных страниц. Отдельная страница допустима только после индивидуальной оценки кандидата и отдельного утверждения владельцем; в рамках первого образца самостоятельные страницы услуг не назначены. Не создавать заглушки, имитировать активные ссылки и менять маршруты до отдельной реализации WEB.

## 4. Границы

- IA, ID, утверждённая обзорная копия и мини-брифы сохраняются.
- Финальный визуальный дизайн и техническое поведение – Stage 03–05; WEB и Laravel в этой задаче не изменяются.
- Дословный текст страницы направления утверждается отдельно. Статус рабочей задачи – в [WORK_MAP](WORK_MAP.md).
