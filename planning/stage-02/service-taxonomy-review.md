# Stage 02 – предложение по ревизии коммерческого каталога

**Статус:** `classification_review_pending`, решение владельца по конкретным новым записям и ID **не получено**. Этот документ не изменяет утверждённую карту Stage 01, исходные 81 ID, названия, URL или тестовые baseline.

## Новые уточнения владельца 10.11.2026

- **Фармацевтический кейс:** молекулярный R&D, биопрепараты/антитела, дженерики и формуляции – предмет конкретно выполненных работ. Не использовать эти наименования как единственное или исчерпывающее предложение прикладного AI и не объявлять каждый кейсовый сюжет самостоятельной услугой. Обзорное направление сформулировать широко: AI-агенты, RAG/знания, документы, компьютерное зрение, моделирование, аналитика, автоматизация и другие задачи в разных отраслях; отдельные конкретные возможности сверять с Services и технической командой.
- **Кибербезопасность:** выделить заметную специализацию в технологическом предложении, без перегрузки общей страницы. Отдельная страница должна разбирать аудит/пентест, веб/API, DevSecOps, инфраструктуру/доступ, данные, мониторинг и реагирование по исходному документу программиста. Пока не добавлять вымышленные SLA, круглосуточную поддержку, сертификаты и юридические гарантии.
- **Маркетинг:** SEO/GEO, международное продвижение, контент и PR в реестре частично перекрываются на уровне названий и описаний. В обзорной странице сгруппировать без повторов; для подробных страниц развести намерения, реальные результаты работ и области ответственности. Не удалять машинные записи только из-за похожих слов.

## Протокол согласования изменений

1. Сопоставить каждую затронутую запись `svc-*` из `planning/stage-01/catalogue-map.json` с оригинальным реестром Services, подтверждённым коммерческим предложением и пояснениями профильных специалистов.
2. Составить явную таблицу `старый ID / старое название / новая категория / действие: оставить | переименовать | объединить | перенос в кейс | архивировать / предлагаемая публичная формулировка / основание`.
3. Представить владельцу на утверждение каждое изменение и новые потребности в URL. Без решения не редактировать baseline 17/81, `references/project/services_catalogue.json`, синхронизированные источники или автоматические тесты. После решения обновить все источники и тесты одним согласованным набором с историей идентификаторов.
4. Пока пересмотр не завершён, редактор может профессионально **обобщать** названия на обзорных карточках, но не утверждать, что старые кейсовые категории – новые самостоятельно продаваемые услуги.

**Открытая задача:** реальная пересчитанная численность каталога после уточнений неизвестна. Историческое 17/81 остаётся техническим baseline до прямого утверждения ревизии, не рекламной цифрой новой страницы без проверки состава.
